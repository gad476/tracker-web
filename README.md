# مسار التأسيس — صفحة تتبع تفاعلية لإطلاق منصة تسويق ووساطة عقارية

صفحة (`index.html` + `app.js` + `config.js`) تعمل على **GitHub Pages**، وتستخدم **Firebase Firestore** (مجانًا) كقاعدة بيانات مشتركة: كل من يفتح الرابط يرى نفس المهام والفريق، وأي تعديل من أي عضو يظهر لحظيًا لدى البقية دون تصدير أو استيراد يدوي. تتيح:

- عرض مراحل تأسيس المشروع كبطاقات متجاوبة (بدون أي تمرير أفقي، تتكيف مع كل أحجام الشاشات)، مع نسبة إنجاز لكل مرحلة، وإمكانية **إضافة/تعديل/حذف المراحل** مباشرة من الصفحة.
- إضافة/تعديل/حذف المهام، مع: العنوان، الوصف، المرحلة، **المسؤول عن التنفيذ**، **من أضاف المهمة**، **تاريخ التحديد**، **تاريخ الاستحقاق**، **تاريخ الإنجاز**، و**نسبة إنجاز رقمية (0-100%)** يحددها المسؤول عبر شريط تمرير مباشر من بطاقة المهمة أو من نموذج التعديل — تصل المهمة تلقائيًا لحالة "منجزة" عند 100% ولحالة "لم تبدأ" عند 0%.
- **سجل إجراءات** لكل مهمة (زر 🕘 على بطاقتها): من أنشأها، من عدّلها، كل تغيير في نسبة الإنجاز، من أنجزها أو أعاد فتحها — بالترتيب الزمني مع التاريخ والوقت.
- حساب تلقائي لـ **نسبة الإنجاز الكلية** (متوسط نسب إنجاز كل المهام، وليس فقط عدد المهام المكتملة بالكامل)، وعدد المهام **المتأخرة حاليًا**، و**متوسط أيام التأخير** للمهام المُنجزة (الفرق بين تاريخ الاستحقاق وتاريخ الإنجاز الفعلي).
- قسم **فريق العمل**: **إضافة/تعديل/حذف** أعضاء، كل عضو بلون تمييز خاص به، وبطاقة لكل عضو تعرض عدد المهام المُكلَّف بها، ونسبة إنجازه (بنفس منطق المتوسط)، وما أضافه من مهام.
- محدد "أنت الآن" أعلى الصفحة: يُستخدم لتسجيل من أضاف المهمة تلقائيًا، ومن قام بكل إجراء عليها (تعديل، تحديث نسبة، إنجاز، إعادة فتح).

## ⚠️ ملاحظة حول تحديث نسخة سبق نشرها

إن كنتم تحدّثون نسخة كانت تعمل من قبل (قبل إضافة ميزة "إدارة المراحل")، فسيقوم التطبيق تلقائيًا **ولمرة واحدة فقط** بتفريغ كل المراحل والمهام القديمة، واستبدالها بمرحلة واحدة باسم "المرحلة الأولى" تحتوي على مجموعة مهام افتراضية أولية — **مع الإبقاء على فريق العمل الحالي كما هو دون أي تغيير**. هذا يحدث تلقائيًا أول مرة تُفتح فيها الصفحة المحدَّثة، ولا يتكرر بعد ذلك. عدّلوا أو احذفوا أو أضيفوا مهامًا ومراحل جديدة بحرية بعدها من داخل الصفحة نفسها.

## الخطوة 1 — إنشاء مشروع Firebase مجاني (٣ دقائق)

1. افتح [console.firebase.google.com](https://console.firebase.google.com) وسجّل دخولك بحساب Google، ثم اضغط **إنشاء مشروع (Add project)** واختر اسمًا (مثلاً: real-estate-tracker). يمكنك تعطيل Google Analytics في هذه الخطوة، فهو غير مطلوب.
2. من القائمة الجانبية داخل المشروع: **Build → Firestore Database** ← اضغط **إنشاء قاعدة بيانات (Create database)**. اختر أي موقع خادم قريب، وابدأ في **وضع الاختبار (Test mode)** (سنُحكم قواعد الأمان بعد قليل).
3. عد إلى الصفحة الرئيسية للمشروع ⚙️ (إعدادات المشروع) → بأسفل قسم "عام" ابحث عن **تطبيقاتك (Your apps)** ← اضغط أيقونة الويب `</>` ← أعطِ التطبيق اسمًا واضغط تسجيل. ستظهر لك كائن `firebaseConfig` يحتوي على القيم (apiKey، authDomain، projectId...).
4. انسخ هذه القيم إلى ملف `config.js` في هذا المشروع، مكان الحقول التي تبدأ بـ`ضع_...`.

### تأمين قاعدة البيانات (مهم)

بعد التأكد من أن الصفحة تعمل، عدّل قواعد الأمان حتى لا يستطيع أي شخص على الإنترنت الوصول إليها إن عرف رابط مشروعكم: من **Firestore Database → Rules** استبدل المحتوى بما يلي، ثم اضغط **نشر (Publish)**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /workspaces/{workspaceId} {
      allow read, write: if workspaceId == "القيمة_التي_وضعتها_في_WORKSPACE_ID_داخل_config.js";
    }
  }
}
```

هذا يسمح بالقراءة والكتابة فقط لمن يعرف معرّف مساحة العمل (WORKSPACE_ID) المحدد في `config.js` — وهو حماية بسيطة مناسبة لفريق صغير يتشارك رابطًا داخليًا، وليست حماية كاملة على مستوى الأفراد (فلا يوجد تسجيل دخول لكل عضو). إن احتجتم لاحقًا تحكمًا أدق بالصلاحيات لكل شخص، يلزم إضافة Firebase Authentication، وهي خطوة إضافية يمكن تنفيذها لاحقًا عند الحاجة.

## الخطوة 2 — النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub (أو استخدم مستودعًا موجودًا).
2. ارفع الملفات الأربعة: `index.html`، `app.js`، `config.js` (بعد ملء بياناتكم فيه)، وهذا الملف، إلى جذر المستودع.
3. من إعدادات المستودع: **Settings → Pages**، اختر المصدر (Source) **Deploy from a branch**، ثم اختر الفرع `main` والمجلد `/root`.
4. بعد دقيقة أو دقيقتين ستظهر الصفحة على رابط من نوع:
   `https://USERNAME.github.io/REPO-NAME/`

لا حاجة لأي بناء (build) أو تثبيت حزم — الصفحة تعمل كملفات ثابتة، وتتصل بـ Firebase مباشرة من متصفح كل زائر.

## كيف تعرف أن التزامن يعمل

- عند فتح الصفحة لأول مرة تظهر رسالة "جارٍ الاتصال بقاعدة البيانات…" لثوانٍ ثم تختفي.
- أعلى يسار الصفحة (بجانب "أنت الآن") يظهر مؤشر: **● متزامن** (أخضر) يعني أن كل شيء محفوظ ومشترك بنجاح. **● جارٍ الحفظ…** يظهر للحظة عند أي تعديل. **● تعذّر الاتصال/الحفظ** (أحمر) يعني وجود مشكلة في `config.js` أو قواعد الأمان أو الاتصال بالإنترنت — راجع الخطوات أعلاه.
- إن لم تُملأ بيانات `config.js` بعد، ستظهر رسالة توضيحية بدلاً من الصفحة تطلب إكمال هذه الخطوة أولًا.

## ⚠️ ملاحظة حول "أنت الآن" (currentUser)

هوية "أنت الآن" المختارة من القائمة أعلى الصفحة تُحفظ **محليًا في متصفح كل شخص فقط** (وليست في قاعدة البيانات المشتركة)، حتى يحتفظ كل جهاز بهويته الخاصة رغم أن الجميع يرى نفس المهام والفريق. إن مسح شخص بيانات المتصفح أو فتح الصفحة من جهاز جديد، سيُطلب منه اختيار اسمه من القائمة مجددًا.

## التصدير/الاستيراد كنسخة احتياطية

زرّا **تصدير/استيراد** ما زالا موجودين، لكن دورهما الآن تغيّر: التصدير يُنزّل نسخة احتياطية من كامل البيانات المشتركة، والاستيراد **يستبدل بيانات كل الفريق** (وليس متصفحك فقط) بمحتوى الملف المستورد — استخدمه بحذر، وهو مفيد أساسًا كنسخة احتياطية دورية أو لنقل البيانات بين مشروعي Firebase مختلفين.

## البنية

```
index.html   الهيكل والتنسيقات (RTL / خطوط عربية / تصميم) + مؤشرات الاتصال
app.js       منطق البيانات، التزامن مع Firestore، الحسابات، الرسوم البيانية
config.js    بيانات مشروع Firebase الخاص بكم (تُملأ مرة واحدة فقط)
```

## التخصيص

- عدّل مصفوفة `PHASES` في أعلى `app.js` لتغيير أسماء/عدد مراحل مشروعكم.
- عدّل دالة `seedData()` لتغيير المهام والعضو الافتراضيين اللذين يظهران عند أول إنشاء لقاعدة البيانات (تُستخدم مرة واحدة فقط، أول مرة لا يوجد فيها مستند بعد).
- لتشغيل أكثر من فريق/مشروع منفصل بنفس حساب Firebase الواحد، فعليك فقط استخدام قيمة مختلفة لـ`WORKSPACE_ID` في `config.js` لكل نسخة، مع تحديث قاعدة الأمان لتشمل كل القيم المسموح بها.
